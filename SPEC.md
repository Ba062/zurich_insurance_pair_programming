# SPEC
Purpose: what it does and who uses it
Data: the fields and types (for example claim id, customer, amount, stage)
Database: tables and columns
Backend: endpoints, what each takes and returns
UI: screens and what the user can do
Rules: business rules, kept in one place
Edge cases: empty input, wrong input, what happens on failure
Constraints: plain code, few files, no extra packages
Who owns what: Jethro = ..., Partner = ...
Done means: the 3 or 4 things that must work in the demo
